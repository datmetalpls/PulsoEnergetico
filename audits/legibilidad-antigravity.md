# Auditoría de legibilidad y mantenibilidad — Pulso Energético

## Resumen ejecutivo
La base de código es compacta (~3.479 líneas totales entre `backend/` y `frontend/src/app/`) y mantiene una buena separación general entre motor puro (`engine.py`), servicios (`services.py`), serialización (`serializers.py`) y vistas (`views.py`).
El principal problema de incorporación inmediata es la **ausencia de un `README.md` en la raíz** y desajustes menores en los README de subproyectos frente al estado actual (`operador_demo` y funciones P3 recortadas).
En el frontend (`app.component.html`, `pulso-store.service.ts`, `mock-data.service.ts`) se concentra la mayor deuda de legibilidad: templates y servicios monolíticos, código muerto de P3 aún cableado, duplicación del formulario de login y de cálculos mock, y cero pruebas unitarias (`*.spec.ts`).
En el backend la lógica es clara y tiene 13 pruebas funcionales en PostgreSQL, aunque `views.py` agrupa demasiadas acciones en funciones largas y falta documentación (`docstrings` y `__str__` en modelos).
Para la demo de mañana basta con ajustes quirúrgicos de texto/documentación (10–25 min); los refactors estructurales quedan para después.

## Lo que está bien
- **`backend/energy/engine.py`**: función pura `integrate()` de 20 líneas, muy clara, tipada con `@dataclass(frozen=True)` y compartida entre ingesta y comparación.
- **`backend/energy/models.py` y `serializers.py` / `views.py`**: nombres de campos alineados con `docs/02-contrato.md` (`voltage_v`, `current_a`, `power_w`, `energy_wh`, `threshold_wh`, `elapsed_s`, `on_seconds`), manejo explícito de transacciones (`select_for_update`), validación centralizada (`number`, `boolean`, `fields_only`, `APIError`) y 13 pruebas automáticas sobre PostgreSQL 17.
- **`frontend/src/app/utils/format.ts` y `models/pulso.models.ts`**: formateadores `es-CL` bien encapsulados (`formatPower`, `formatEnergy` con distinción `bench` vs `venue`) e interfaces TypeScript fieles al contrato JSON.
- **Estilo y accesibilidad base (`styles.css` y `app.component.html`)**: variables CSS por franja (`theme-day`, `theme-afternoon`, `theme-night`), `tabular-nums`, `prefers-reduced-motion` y etiquetas `aria-*` consistentes.
